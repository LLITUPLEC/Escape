# Глобальный босс

Один запас здоровья для всех игроков. Неделя начинается в понедельник в00:00 по Москве (воскресенье21:00UTC). Идентификатор события `week-<starts_at>`. Незавершённый босс уходит в конце недели без наград; следующая неделя получает новый запас здоровья и три попытки на каждого игрока.

Одна попытка расходует один предмет `global_boss_teleport`. Новый запрос содержит `session_epoch`, UUID `request_id` и `event_id` из `duel_global_boss_get`. При повторе нужно сохранить ВСЕ эти значения. `event_changed` требует обновления состояния и нового явного действия игрока. Повтор запроса или восстановление после падения возвращает ту же попытку. Сдача, уход и истечение20секунд отсутствия расходуют попытку. Если другой игрок убил босса до первого принятого действия, возвращаются телепорт, попытка и применённый эликсир.

`duel_global_boss_get` возвращает состояние общей недели, счётчик попыток, телепорты в сумке, недельный вклад `my_damage` и доступную для продолжения попытку. `duel_global_boss_enter` возвращает обычный `match_id`; присоединение через стандартный WebSocket `match_join`, только владельцу.

В бою работают обычные экипировка, достижения, аура, эликсир и пять способностей. Босс сохраняет обычный AI и ману. Лечения у него нет. Его собственные ходы нумеруются с1, включая дополнительные ходы за5+; петарда, щит, ярость и крик сами счётчик не увеличивают. На каждом новом ходеn текущий урон умножается на`1+n/100` с сохранением дробной части, текущий крит растёт наn процентных пунктов до100%. Крик на ходах1,3,5… наносит20% первоначального максимального здоровья героя, игнорирует броню, не расходует ману и не завершает ход.

Попытка ограничена30 ходами игрока. Бои босса не выдают обычный опыт/добычу шахты, не увеличивают обычные счётчики PvE/PvP/ежедневных заданий. Свиток добычи не умножает фиксированное содержимое почтового сундука.

Каждое действие сохраняет общуюHP, монотонный номер, точный снимок поля/статистики и вклад одной CAS-транзакцией. До подтверждения транзакции клиент не получает результат и следующий ввод не принимается. Повтор после потери ответа не наносит урон повторно. После падения продолжается сохранённое поле, здоровье, мана и эффекты; телепорт повторно не списывается.

В `BoardSync` поля `globalBossMyDamage` и в `GameOver` поле `bossMyDamage` относятся к текущей попытке. `globalBossTotalDamage`/`bossTotalDamage` — сумма за неделю. ОбщаяHP передаётся обычными `bHp`/`bMaxHp`; чужой вклад нельзя показывать как урон владельца. Дополнительные поля: `bossOwnTurn`, `bossScreamCooldown`, `bossScreamTriggered`, `bossScreamDamage`, `bossPlayerTurnsLeft`.

После общей победы каждый участник с положительным уроном получает одно письмо: один случайный легендарный рецепт из8слотов, тессеракт, случайный эликсир, свиток добычи,1500золота,2000руды и5материи. Минимум вклада редактируется конфигом, по умолчанию1. Почта приходит офлайн. Её создание и защищённый флаг участника атомарны; удаление старой истории не позволяет создать награду заново. Почтовый сервис работает только пока есть незавершённая рассылка. Единый `nk.run_once` запускает временный восстановитель, который поднимает недоставленные события, включая прошлые недели, без RPC игрока.

`duel_mail_get` возвращает `{ok,unread_count,messages?}`. Сообщение: `{id,title,body,created_at,claimed,attachments:[{def_id,amount}|{resource,amount}]}`. `duel_mail_claim` принимает `{session_epoch,message_id}` и возвращает `{ok,claimed,delivered_items?,pending_items?,resources,unread_count}`. Одинаковые и параллельные запросы выдают награду один раз. Полная сумка сохраняет предметы в защищённой очереди. Все неполученные письма сохраняются, полученная история ограничена4сообщениями.

Параметры находятся в системном `duel_global_boss/config`, образец — `data/global_boss.config.json`. Изменения применяются к НОВОМУ недельному событию: текущая неделя сохраняет свой снимок. HP округляется вверх кратно50000, базовый урон — кратно500. По умолчанию550000HP,3500урона,1000брони,5%крита. Настройка через существующий Console helper `tools/storage_admin.py` с alias `global-boss`; alias `shop` управляет `duel_shop_catalog/v1`.

Защищённые коллекции: `duel_global_boss`, `duel_global_boss_player`, `duel_global_boss_attempt`, `duel_mail`. Общий Storage guard запрещает любые клиентские записи/удаления по префиксу`duel_`, включая создание первой строки.

## Данные раздела и рейтинг (0.3.14)

`duel_global_boss_get` дополнительно возвращает `base_damage`, `base_armor`, `base_crit` (0…1), `base_heal=0`, `no_healing=true`. Вместе с `hp_max` и `max_turns` это исходные характеристики текущего недельного события. Изменение системного конфига для следующей недели не меняет эти значения.

`duel_global_boss_leaderboard_get` принимает `{event_id,limit:20,cursor?,session_epoch?}`. Максимум — 50 строк за запрос. Ответ: `{ok,event_id,entries?,self_entry,next_cursor?,prev_cursor?,updating}`. Строка: `{rank,user_id,display_name,avatar_id,damage,attempts_used,is_self}`. `damage` — сумма фактически снятой общей HP за все попытки игрока в этой неделе; отдельные попытки не создают отдельные строки. Своя позиция возвращается и за пределами текущей страницы. Нулевой вклад имеет `rank=0`. Пустой массив `entries` опускается для совместимости с Unity JsonUtility.

Основа рейтинга — защищённый `duel_global_boss_player/<event_id>`, который обновляется в одной CAS-транзакции с общей HP и снимком попытки. Native leaderboard `escape_boss_<event_id>` является производной проекцией: authoritative, сортировка по убыванию, оператор `best` над **уже суммированным** недельным вкладом. Повтор или запоздавшая запись не прибавляют урон ещё раз и не уменьшают более свежую сумму. В публичную metadata не записываются идентификаторы наград, запросов или попыток. Имена и аватары собираются отдельно из текущего публичного пользователя и разрешённого выбранного образа. [Правила операторов Nakama](https://heroiclabs.com/docs/nakama/concepts/leaderboards/).

Контроль восстановления находится в `duel_global_boss_rank`. Временный сервис `duel_global_boss_rank_dispatcher` восстанавливает проекцию по 100 исходных строк за тик. Он запускается после сбоя записи и при старте сервера; после завершения прекращает работу. Повторный запуск также безопасен. `updating=true` означает, что восстановление ещё проходит по исходным данным.

Ошибка проверки существования сервисного матча не считается доказательством его отсутствия: при такой ошибке новый обработчик не создаётся. Если прежний обработчик достоверно заменён другим, его следующий тик завершает старый сервис вместо бесконечного повторения предупреждения.

## Таймер и сигналы эффектов (0.3.14)

`turnPaused` обозначает ожидание анимации/готовности, `turnDurationSeconds=30` позволяет показать статический полный таймер в этой фазе. После OP17 сервер немедленно рассылает `turnPaused=false` и зафиксированный абсолютный `turnEndsAtUnixMs`; то же делает резервный запуск через 8 секунд без OP17. Повторный ACK не запускает отсчёт заново. Снимок, изменение общей HP другим игроком и способности, сохраняющие ход, не сдвигают дедлайн. Дополнительный ход и смена действующего персонажа получают новую фазу ожидания, затем новый отсчёт. Сервер проверяет истечение по тем же абсолютным миллисекундам; бот не выполняет запоздавший обычный ход после нуля.

Входящий OP13 на границе `now >= turnEndsAtUnixMs` отклоняется с `turn_expired` до расхода маны, установки перезарядки и расчёта поля. Затем применяется обычный пропуск хода по таймеру. Поэтому опоздавшая способность или комбинация 5+ не продлевает уже истёкшее решение. В обычных режимах аналогичная проверка использует существующий серверный tick deadline. Ожидание OP17 не считается истёкшим решением; OP17 и допустимый запрос в одном пакете используют новый запущенный срок.

`bossAdaptationTriggered` передаётся только в результате нового собственного хода босса. `bossScreamTriggered` и `bossScreamDamage` также относятся только к передаваемому действию. `bossActionSequence` — сохранённый номер принятого действия для устранения повторной презентации. Начальный снимок, запрос OP16, ACK таймера и переподключение содержат эти флаги выключенными, даже если в сохранённом состоянии предыдущий ход применял крик. Интерфейс не должен запускать эффект только по ненулевому `bossOwnTurn`.
