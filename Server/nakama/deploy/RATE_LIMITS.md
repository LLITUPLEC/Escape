# Ограничения запросов Escape

Защита состоит из Nginx внутри Compose-проекта `escape` и общего ограничителя
пользователя в Lua. Другие сайты на сервере используют свои прежние маршруты.

Nginx `1.30.6-alpine` принимает API на `127.0.0.1:27350` и Console на
`127.0.0.1:27352`. Прямой API Nakama на хост не опубликован. Прямой Console
`127.0.0.1:27351` остаётся для SSH-туннеля.

| Область | Постоянная частота | Допустимый краткий всплеск |
| --- | --- | --- |
| API с одного IP | 20 запросов/с | 80 избыточных запросов |
| Вход/регистрация/обновление сессии с IP, общий бюджет | 12 запросов/мин | 12 избыточных запросов |
| Console с одного IP | 10 запросов/с | 40 избыточных запросов |
| Вход/MFA/смена пароля Console с IP, общий бюджет | 6 запросов/мин | 5 избыточных запросов |
| RPC чтения одного игрока | 240 запросов/мин | ёмкость 60 токенов |
| RPC изменения одного игрока | 120 запросов/мин | ёмкость 20 токенов |
| Создание боёв/очередь/матчмейкер одного игрока | 6 запросов/мин | ёмкость 4 токена |
| Захват сессии/удаление аккаунта одного игрока | 12 запросов/мин | ёмкость 4 токена |
| Сообщения в одном бою от одного игрока | 20 сообщений/с | ёмкость 30 токенов |

Nginx дополнительно допускает до 40 одновременных активных API-соединений с IP
и до 20 для Console. Сообщения боя свыше 4096 байт отбрасываются до разбора.
Обычное обновление панелей каждые 5 секунд укладывается в эти бюджеты.

Лимиты IP суммируются для игроков за одним NAT. Лимиты игрока общие для всех
его токенов, устройств, RPC в одной категории и HTTP/WebSocket-вызовов. Запросы,
которые отклонены бизнес-логикой, тоже расходуют токен. Неизвестные новые RPC
по умолчанию попадают в категорию изменения. При необходимости частоты меняются
в `nginx.conf.template` и `duel_api_rate_limit.lua`; допустимую нагрузку следует
проверять на реальном числе игроков.

Превышение возвращает HTTP `429`, код Nakama `8` и `rate_limited` с
`retry_after_seconds`. Nginx также выдаёт заголовок `Retry-After`. Повторять
изменяющие запросы автоматически без проверки их результата нельзя. В бою
лишние сообщения отбрасываются, ответ об ограничении отправляется максимум
один раз в секунду. Прямое создание клиентского relayed-матча отключено:
Escape создаёт authoritative-матчи серверными обработчиками.

## Доверенный адрес прокси

`CADDY_PROXY_IP` в серверном `.env` содержит **один точный** адрес шлюза
`escape_default` (`172.22.0.1` на текущем сервере). Определять его следует через:

```sh
docker network inspect escape_default --format '{{(index .IPAM.Config 0).Gateway}}'
```

Для первоначальной установки сеть можно предварительно создать
`docker network create escape_default`, затем передать найденный адрес
`init_config.py --caddy-proxy-ip <IP> --client-key-file ... --catalog-dir ...`.
При изменении Docker-сети перепроверить шлюз, обновить `.env` и пересоздать
только `api-gateway` этого проекта.

Caddy обязан устанавливать `header_up X-Real-IP {remote_host}` для двух
маршрутов. Nginx доверяет этому заголовку только от указанного шлюза и полностью
заменяет внешний `X-Forwarded-For` перед отправкой в Nakama. Пользовательские
заголовки не могут выбирать другой IP через публичный домен. Локальный root
и сервисы на доверенном хосте входят в границу доверия этой схемы.

Журнал доступа Nginx содержит IP, метод, путь и статус; параметры запроса
с WebSocket JWT в него не попадают. Обычные error-строки Nginx с полным URI
подавлены, чтобы JWT не оказался в журнале при отказе подключения.

## Общий бюджет игрока

Объект `duel_api_rate_limits/v1` принадлежит аккаунту; права чтения и записи
равны `0`, а storage-hook запрещает игрокам создание, изменение и удаление
всей коллекции. На пользователя сохраняется ровно один объект с четырьмя
фиксированными группами. Он удаляется вместе с аккаунтом.

Каждый RPC выполняет чтение и условную запись с версией. Конкурирующий вызов
не может потратить уже использованный токен: он перечитывает баланс. Число
повторных попыток ограничено четырьмя; ошибки базы отклоняют запрос. Такое
решение добавляет операцию чтения и записи на каждый RPC и сохраняет защиту
между Lua VM и перезапусками сервера. Сообщения игрового поля ограничиваются
в единственном последовательном состоянии authoritative-матча без запросов
к базе на каждое выделение клетки.

Проверки: `api_rate_limit_security_test.lua` покрывает переполнение, возврат
токенов, параллельные условные записи, первый конкурентный запрос, ошибки БД,
отдельных пользователей, нормальный опрос каждые 5 секунд, RPC/RT-хуки и
фильтр сообщений боя. `storage_guard_security_test.lua` проверяет запрет
клиентской подмены и удаления бюджета.
