# Проверка безопасности Escape — 22 октября 2026

Проверены клиент Unity, Lua-модули Nakama и отдельное развёртывание на
`prokrust-play.ru`. Это целевая проверка исходников и API, не исчерпывающий пентест.
Исходные локальные изменения материалов и тестового каталога владельца сохранены.

## Исправлено

- Удалён RPC очистки рейтингов. Файл оставлен пустым модулем, чтобы обновление
  перезаписало опасную старую версию; администратор работает через Console API.
- Запрещено принимать результаты боёв от клиента. Authoritative match handler
  записывает статистику с CAS, идентификатором результата и защитой от повторов.
  Выход из матча принимается только от присутствующего участника начавшегося боя.
- Request hooks блокируют клиентские create/update/delete любых `duel_*` и `arena_*`
  коллекций, включая первую запись и смешанные batch-запросы. Одного
  `permission_write=0` недостаточно для защиты от создания поддельного профиля.
- Preview rows разрешаются только по user ID в системном Storage. Пользовательские
  whitelist, email/metadata и встроенные тестовые адреса больше не дают привилегий.
- Прямая смена username через стандартный UpdateAccount запрещена; изменение
  проходит через игровые проверки и оплату `duel_nickname_change`.
- Получение достижения и ресурсы записываются одной транзакцией с CAS обоих объектов.
  Продажа, запуск/ускорение крафта и PvE-награды также используют атомарные batch-записи.
  Защищены гонки двойной продажи, восстановления проданного предмета, расхода ресурсов
  и перезаписи кошелька при выдаче рецепта. Первые записи используют create-only CAS.
- Клиент больше не сохраняет пароль email, удаляет прежнее значение Base64 и
  восстанавливает вход через refresh/linked device. Новые device credentials —
  случайные UUID. Сохранённые идентификаторы не меняются. Проверяется, что device
  fallback возвращает ожидаемый email-аккаунт; конфликт требует ручного входа.
- Авторизация привязана к endpoint. Переход на чистую базу нового домена однократно
  очищает прежние email-токены и session epoch, сохраняя идентификатор устройства.
- Для Escape созданы отдельные контейнеры, БД, сеть и случайные серверные секреты.
  API/Console привязаны к localhost, БД не публикует порт; внешний API работает через
  HTTPS/WSS. Корневая ФС Nakama доступна только для чтения, capabilities удалены,
  повышение привилегий запрещено, память/CPU/логи ограничены.
- Проверка чистого сервера выявила ошибки отложенной инициализации барьеров и
  функций доски. Зависимости разрешаются через заранее созданную таблицу Runtime;
  каталог, запуск поля, завершение реального PvE и запись результата проверены на сервере.
- JWT/refresh/device ID перенесены в защищённое хранилище: Windows DPAPI,
  Android Keystore/AES-GCM, iOS/macOS Keychain. Проверенная миграция сохраняет
  аккаунт и удаляет открытые копии только после успешной записи и чтения.
  Подробнее — [SECURE_CREDENTIALS.md](SECURE_CREDENTIALS.md).
- Включены IP-лимиты Nginx и общий CAS-бюджет пользователя для всех 44 RPC,
  действующий через HTTP и WebSocket. Ограничены подключения и сообщения боя.
  Проверены реальный ответ 429, восстановление бюджета и невозможность подменить IP.
  Настройки — [deploy/RATE_LIMITS.md](deploy/RATE_LIMITS.md).
- Dashboard `https://console.prokrust-play.ru` настроен через отдельный защищённый
  gateway; админ-авторизация проверена, попытки входа ограничены.
- Исправлены старые локальные достижения и мерцание ресурсов: кэши привязаны к
  серверу и user ID, пустой прогресс заменяет локальные значения, старые ответы
  отбрасываются; сохранение и обновление UI выполняются на главном потоке.
  Epoch больше не читает PlayerPrefs из фоновых Nakama callbacks.

## Проверки

Девять Lua mock suites покрывают поддельные результаты, replay, запрещённые Storage-записи,
whitelist, обход цены nickname, конкурентные транзакции, ошибки хранилища и
параллельную инициализацию. Дополнительно выполнены проверка реальным runtime Nakama,
запуск контейнеров и 25 HTTP/WebSocket проверок на временном аккаунте, включая
реальный PvE-матч, сдачу и единственную запись поражения. Тестовые аккаунты удалены.

Клиент: компиляция полного Assembly-CSharp через Roslyn для Windows Editor и
Android Player и Assembly-CSharp-Editor, 13 проверок защищённого хранилища
(включая настоящий DPAPI), 14 регрессионных проверок кэша. Java-плагин компилируется
с Android SDK. Сборки на реальном Android/iOS/macOS и визуальная проверка Play UI
не выполнялись; работающий Unity не останавливался. TMP получает сохранение перед
целевым переимпортом только вне Play Mode; предусмотрено меню восстановления,
сам изменённый владельцем шрифтовой asset не заменяется.

## Следующие задачи

1. Проверить защищённое хранилище на подписанных мобильных/Apple сборках и выполнить
   отдельную безопасную ротацию ранее открытых device ID. Само перемещение в vault
   не отзывает исторические копии из бэкапов. Logout сохраняет device association.
2. Провести нагрузочное тестирование и подобрать лимиты под реальные NAT/онлайн.
   Общий CAS-бюджет делает дополнительные обращения к БД; для роста нагрузки стоит
   профилировать I/O и CPU отдельно. Лимиты приложения не заменяют внешнюю DDoS-защиту.
3. Добавить постоянную очередь повторной выдачи наград/записи результатов при
   длительном сбое БД. CAS предотвращает двойную выдачу и частичные транзакции,
   но после исчерпания попыток награда/статистика может остаться несохранённой.
4. Настроить регулярные резервные копии и проверку восстановления.

На хосте у ранее существующих проектов PostgreSQL/Nakama/Console привязаны к
`0.0.0.0`. Доступность извне зависит от firewall; настройки этих проектов не
менялись по прямому указанию владельца. Новое развёртывание Escape их не использует.
