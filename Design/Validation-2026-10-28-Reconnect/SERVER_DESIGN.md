# Восстановление и отмена матчей — 0.3.17

## Причина зависания

Клиент повторно вызывал `duel_session_claim` при каждом новом WebSocket. Сервер повышал epoch аккаунта, но живой матч сохранял прежний `owner_session_epoch`: бот и BOARD_SYNC продолжали работать, а действия владельца отклонялись как устаревшие. В 0.3.17 транспортное переподключение больше не создаёт новую логическую сессию; после настоящей новой авторизации серверный recover проверяет актуальный epoch и участника, отзывает старое presence и привязывает новый epoch. Запоздалый leave старого сокета не удаляет замену. OP12/13/17 старой сессии отклоняются.

После холодного запуска клиент также не обнаруживал уже оплаченный матч и упирался в active lease. Новый серверный указатель активного матча служит только кандидатом для поиска: обязательны `match_get` и проверка участника в самом матче. Ошибка проверки не разрешает очистить живой lease. Восстановление не снимает повторную оплату; просроченный orphan reservation проходит каноническое восстановление. Временная практика босса не участвует в этом механизме.

## Граница начала и отмены

Флаг `started` означает готовность транспортного матча, а не совершённую игровую попытку. До commit сохраняется `_prestart_pending`. Commit выполняется при допустимом OP17, первом реально допустимом действии **до** списания маны/эффектов либо существующем fallback готовности через 8 секунд; актуальность сессии обязательна. Во время reveal эликсир только отображается, а фактически закрепляется при commit.

Неигранный матч ограничен существующим admission deadline в 20 секунд. Проверка выполняется до раннего перехода в boss loop и охватывает joined reveal с устаревшим владельцем. Она не отменяет сыгранные матчи или арену. Неудачный CAS возврата сохраняет состояние для повторной попытки, а не выдаёт успешное подтверждение.

## Оплата и совместимость

Отмена связана с неизменяемыми receipt/token, run и match ID. PvE возвращает исходные entry charges, Race — исходные ставки каждого участника, платный босс — соответствующие попытку и телепорт. Повторная отмена не возвращает средства дважды и не создаёт победу, статистику или награду. После commit обычная сдача сохраняет игровые расходы.

При ограничении вместимости остаток возврата хранится как долговечный credit. `refund_recorded=true` допустим только после сохранения выплаты или остатка; ошибка записи не считается подтверждением. Позднейший recovery доплачивает остаток после освобождения места, а повторный cancel обновляет фактический статус возврата.

Контракт 0.3.16 сохранён: старые payload без request ID принимаются, prestart forfeit использует безопасную отмену, сыгранный forfeit остаётся сдачей. Исправление повторного claim на клиенте входит в 0.3.17. Новые recover/cancel API добавлены без удаления старых. Cancel без конкретного match/request ID только обнаруживает состояние: задержавшийся запрос не может отменить новый оплаченный бой.

## Доказательства

Итоговый runtime SHA-256: `0c16126510fe0ca50b8f99a72f5cbc6a3a4e71b6e3a3412063e452c4f78058fe` (67 модулей и неизменённый production seed).

- [Локальные проверки](server/local-security-summary-network-final.json): **830 PASS**, исходники во время прогона не менялись.
- [Сетевой итог](server/network-validation-composed.json): **902 PASS** — all 806, recovery 64, reconnect 32. Проверены реальные swap и ability после 5/30 секунд офлайна, cold claim, поздний leave, возвраты и deadline. Production runtime до/после остался прежним AAD.
- [Source equivalence](server/target-source-equivalence-deadline-final.json): target32 завершён в `d4673ded3afd` на том же итоговом runtime; его функция, все helpers и остальной module AST совпадают с финальным `0fa70c111d27`. Изменён только чужой ему consumables fixture. Оригинальный финальный all/recovery отчёт и exit status сохранены отдельно; composed report явно указывает происхождение каждой группы.

Прежние неудачные прогоны не объявлены успешными. В частности, [H](server/network-attempt-h-bounty-fixture-failed.json) сохранил единственный failed assert победы на случайном модификаторе; конкретный случайный affix тогда не логировался. Actual-core тест подтвердил, что canonical `energy_block` заменяет урон бомб ростом характеристики. Финальный fixture задаёт `mana_vampire` только собственному тестовому профилю и проверяет фактический BOARD_SYNC, настоящую победу и награду. Другие прежние fixture/transport failures также сохранены в `network-attempt-*-failed.json` и `network-attempt-f-transport.json`; они не подменяют итоговый PASS.

Эта заметка не подтверждает production deployment: применение и публикация имеют отдельные release reports.
